# CLAUDE.md — Riff

AI music studio (Suno-style): keywords → Claude writes the lyrics → a local music model renders a full song with vocals in any genre; or take an existing track and re-render it as deep house / another style. **V1 is local-first, single-user, no auth**; built so V2 can go hosted + mobile additively. Plan + roadmap: [`docs/RIFF_V1_PLAN.md`](./docs/RIFF_V1_PLAN.md). Phase 0 engine spike results: [`docs/PHASE0_SPIKE.md`](./docs/PHASE0_SPIKE.md).

**Releasing:** `python3 scripts/assemble_changelog.py --release X.Y.Z` folds `changelog.d/` into `CHANGELOG.md`, then `scripts/release_check.sh X.Y.Z` gates the tag (the four version literals agree — root + web `package.json`, `api/health.py::APP_VERSION`, backend `pyproject.toml` — plus tests, build and a clean tree). Never hand-edit `CHANGELOG.md`.

This repo follows the same harness as PursuitAI: pnpm + turbo monorepo, `apps/backend` (FastAPI, async SQLAlchemy, Alembic), `apps/web` (Next.js 15, Tailwind, vitest + RTL, Playwright), Postgres + Redis via docker-compose. Conventions carried over verbatim: feature branch → `develop` (squash), `develop → main` merge commit; `changelog.d/` fragments, never a direct `CHANGELOG.md` edit; every new setting lands in `.env.example` in the same PR; every web UI behaviour change ships a vitest test; **clickable mock before any screen** (UI brief: intuitive and easy to use first, then a cool modern design — never a default-template look); a module that opens its own DB session gets a conftest redirect fixture; charge-after-validation on every Claude call; no hardcoded colors, theme tokens only.

## Layout

- `services/ace-step/` — **the music engine sidecar: ACE-Step 1.5, a pinned git submodule** (`git submodule update --init`). MIT, runs natively on Apple Silicon (MLX for LM/DiT/VAE). Own `uv` venv inside the submodule; weights in `services/ace-step/checkpoints/` (gitignored, ~15 GB: turbo 2B + SFT + LM 1.7B + VAE). Never import it from the backend — the backend only speaks HTTP to it.
- `scripts/engine.sh` — `install | start | stop | status | **supervise**` for the sidecar (`supervise` = health check + restart with backoff; `pnpm dev` runs it that way because the engine dies silently). Runbook: `docs/ENGINE_RUNBOOK.md`. Encodes the Phase 0 startup recipe (one DiT slot, LM lazy-loaded, `PYTHONFAULTHANDLER=1`). REST API on `http://127.0.0.1:8001` (`POST /release_task` → `POST /query_result` → `GET /v1/audio?path=`; `POST /v1/init` switches models; docs in `services/ace-step/docs/en/API.md`).
- `services/stems/` — audio-tools venv: **`demucs` (Meta's reference, PyTorch on MPS) is the stem separator** — `python -m demucs -n htdemucs_ft -d mps -o out --float32 song.wav`, ~40 s per song, stems reconstruct the source (residual 1.8%). **`mlx-audio-separator` is installed but BROKEN — do not use it**: its htdemucs output is ~35 dB quiet AND doesn't sum back to the mix (Phase 0 wasted an hour on it; Whisper hallucinated "music" on its stems). Also here: `mlx-whisper` (`mlx-community/whisper-large-v3-mlx`, ~3 GB cached) for lyric transcription — run it on the **vocal stem**, never the full mix; `pyrubberband` (+ the Homebrew `rubberband` binary) for tempo stretch; `librosa` + `pyloudnorm` for analysis/mastering.
- `spike/` — Phase 0 harness: `run_spike.py` (stdlib REST client; `text2music | cover | init | status`), `run_matrix.sh` (idempotent timing matrix), `lyrics/` (three original fixtures). Outputs in `spike/out/` (gitignored); `spike/out/results.jsonl` is the timing ledger.
- `apps/backend/` — **the API (Phase 1).** FastAPI + async SQLAlchemy + Alembic, `uv` venv, Postgres on **5433** (docker-compose; deliberately not 5432). `app/core/config.py` Settings ↔ `.env.example` (keep in sync). `app/models/__init__.py`: users · songs · generations · jobs (`user_id` on every row). `app/services/jobs.py` = the ONE GPU lane (enqueue → `claim_job` FOR UPDATE SKIP LOCKED → `run_job` w/ heartbeat + `report_progress` → done/failed; `reap_stuck_jobs`; idempotency key dedupes in-flight work; **opens its own sessions → conftest `_redirect_jobs_to_test_engine`**). `app/services/music/` = the `MusicProvider` seam: `acestep.py` (REST client; pins the Phase 0 contract: `bpm` + `vocal_language` always, `thinking=false`, turbo `shift=3`) and `fake.py` (instant WAVs; the test suite never touches the engine — `MUSIC_PROVIDER=fake`). `app/services/generation.py` = the `render` handler (provider → `mastering.py` ffmpeg loudnorm → `Generation` rows). `app/services/ai/lyrics.py` = the Claude seam (Phase 2): `SongBrief` (strict structured output — every field required, `extra=forbid`), `ClaudeLyrics` (`claude-opus-5`, adaptive thinking via `output_config.effort`, cached system prompts, SSE-streamed lyrics, section rewrite) vs `FakeLyrics` (tests / no key → `LYRICS_PROVIDER=auto`); every call records an `ai_call_telemetry` row (own session → conftest redirect; cost from the price table). API: `POST /lyrics/brief` · `POST /lyrics/write` (SSE `{type: delta|done|error}`) · `POST /lyrics/section`. Prompts enforce ROMAN script for hi/ur/pa/bn and no artist names. `app/services/presets.py` = **style presets are DATA** (Create styles + Remix targets, served at `GET /presets`; adding a style = a dict; no artist names — `test_presets.py` enforces). Run tests: `./run_tests.sh` (creates `riff_test`, truncates between tests).
- `apps/web/` — Next.js 15 + Tailwind (tokens from the mocks in `globals.css`/`tailwind.config.js`), vitest + RTL. `features/create/` = the Create screen (Phase 2): `createFlow.js` is the PURE state machine (compose → briefing → writing → ready → rendering → result; `songBody()` builds the POST /songs body — unit-tested), `useCreateFlow.js` wraps it with the API calls + SSE reader (`lib/sse.js`) + section edits (`lib/lyrics.js` mirrors the backend tag grammar), `useJob.js` polls a job to terminal, persists the in-flight id per song in localStorage (reload re-attaches — never pay twice) and slows polling in a hidden tab; `features/player/` = one shared `<audio>` + decoded-peaks `Wave`. `CreatePage.js` is the render layer over those (the compose column collapses to a rail / widens; choice in `localStorage:riff:create:side`). `features/player/PlayerProvider.js` (Phase 3) = the ONE app-wide `<audio>` + bottom bar, mounted in the root layout so playback survives navigation — screens call `usePlayerCtx()` (`play(track, list)`, `toggle`, `seek`, `switchTo` for A/B, `isCurrent`, `progress`); never create a second Audio element. `features/library/` = Library grid + song page over the pure `lib/library.js` (filter/sort/grouping/cover gradient — tested). `components/ui/ConfirmDialog.js` is the themed confirm — never a native `confirm()`. `lib/api.js` returns `null` on 204. Pure helpers/hooks get unit tests; screens get logic tests, not markup tests. **E2E:** `pnpm test:e2e` (Playwright) boots a FAKE-provider API on :8011 (`e2e/run-api.sh`, DB `riff_e2e`) and a second Next dev on :3100 with `NEXT_DIST_DIR=.next-e2e` — the whole Create→Library→delete journey runs in ~6 s with no Claude and no engine.
- **Remix (Phase 4):** `app/services/audio/tools.py` = the audio-tools seam (`RealAudioTools` shells into the tools venv scripts under `app/services/audio/scripts/` — `analyze.py` librosa tempo/key/LUFS, `separate.py` reference Demucs on MPS, `transcribe.py` mlx-whisper on the VOCAL STEM, `vocal_mix.py` the vocal treatment + mix; `FakeAudioTools` for tests/E2E — `AUDIO_TOOLS=fake`). `app/services/remix.py` = the `analyze` and `remix` job handlers (models `Upload`/`Stem`/`Remix`; API `api/uploads.py` + `api/remixes.py`; `MusicProvider.cover()` on the seam). **Reimagine (the default remix approach).** `RemixMode.REIMAGINE` / `REIMAGINE_KEEP`: instead of covering the recording, `ClaudeLyrics.reimagine()` (strict structured output `Reimagined`) reads the transcribed lyrics + measured key/tempo and returns meaning, arc, section-tagged lyrics and an arrangement caption; the handler calls `provider.render()` (NOT `cover`) once per variation. `REIMAGINE_KEEP` renders it INSTRUMENTAL at the **original** tempo and mixes the user's auto-tuned vocal on top (the prompt is told to keep tempo + line order so it lines up). Directions live in `presets.REIMAGINE_DIRECTIONS` (`GET /presets` → `reimagine`); the brief is stored on `remixes.brief` and shown as "What Claude heard". **Why it exists: the user judged beat-driven remixes 'horrible' — forcing a performance into a groove is not the same as understanding a song and re-performing it.** **The vocal contract, learned from the user's ears:** the REAL vocal is the LEAD — auto-tuned per note to the detected key (formant-preserving Rubber Band, strength 0.85, default ON), placed clean and in front; **harmonies/doubles/chops are OFF by default** (stacked pitch-shifted copies collided with the lead and made auto-tune sound "horrible"); in **hybrid** the AI cover is SEPARATED with Demucs and its vocals are **ducked 12 dB under the lead's envelope** so they answer in the gaps; `ai_forward` (−3…4) maps to `ai_level_db = −8 + 2·ai_forward`. Every run renders `takes` variations (default 2). Tempo changes stretch the FINISHED mix (never the source before the cover). Web: `features/remix/` (`remixFlow.js` pure reducer + `useRemixFlow` + `RemixPage`), `/remix?upload=<id>` opens an existing upload (the Library/Create "Remix" buttons post `/uploads/from-generation/{gen}` first).
- **Ports:** Riff never collides with PursuitAI (3000/8000/5432/6379): web **3010**, API **8010**, Postgres **5433**, Redis **6380**, engine **8001**; E2E 3100/8011.
- `docs/`, `changelog.d/` — plan + spike results + mock templates; changelog fragments (one per PR).

## Engine gotchas (learned in Phase 0)

- **The sidecar can die silently.** Three times in the spike the process vanished with no traceback (a Metal-level kill): twice during VAE decode, once idle. It never reproduced across 16 renders under every startup combination — but all three deaths overlapped **another MLX/torch process starting on the box** (stem separator loading, a torch wheel install). Working rule: **one GPU workload at a time** — the job runner serializes renders and stem jobs on a single GPU lane, never launches the stems tool during a render. Also: treat a dropped connection as a retryable failure, and give the sidecar a supervisor/health check. Don't spend a session bisecting it again — the finding and the bisect matrix are in `docs/PHASE0_SPIKE.md`.
- **Don't pre-load two DiT slots.** `ACESTEP_CONFIG_PATH2` keeps a second full model + a second compiled MLX VAE resident. Switch models on demand with `POST /v1/init {"model": "acestep-v15-sft"}` (~20 s) instead.
- **The 5Hz LM is optional.** `thinking=false` skips it; the product's Claude "song brief" supplies BPM/key/structure. Load it lazily only for a feature that needs it; it's auto-skipped for `cover`/`repaint` anyway.
- **Turbo needs `shift=3.0`** (not auto-corrected, unlike `guidance_scale`). 8 steps.
- **Empty `lyrics` ⇒ INSTRUMENTAL** (`is_instrumental(lyrics)` in the API server). A `cover` of a user upload with no lyrics comes back with NO vocals — that's exactly what happened to the user's first remix. Remixing an upload therefore needs either (a) transcribed lyrics (Whisper on the vocal stem) for the "re-sing" path, or (b) the **vocal-keep** path (`spike/vocal_keep.py`: Demucs → cover the instrumental only → mix the real vocal back → −14 LUFS), which is the default for "my own song".
- **Always pass `bpm` and `vocal_language`.** The caption's "118 BPM" is ignored without the LM; `vocal_language` defaults to `"en"` so Hindi/Urdu lyrics must send `hi`/`ur`. Romanized and native-script lyrics both work. Cover strength ≥0.5 keeps the SOURCE tempo; use ~0.4 for a tempo/genre jump.
- **Style presets are data, not code** — caption template + default strength + target BPM. The engine's `genres_vocab.txt` already covers Bollywood/filmi, Punjabi/bhangra, qawwali, ghazal, sufi, Urdu pop, jazz-rap/jazz-hop, boom-bap, neo-soul.
- **XL models (20 GB each) don't fit** on this Mac without freeing disk (~21 GB free after install).
- **Only ONE process talks to the GPU** — the API worker is that process; never run `riff`/demucs/whisper CLI jobs while the API worker is rendering (the engine dies silently under a second Metal client). Reference/source audio for `cover` goes up as `multipart/form-data` (`src_audio` file field); JSON paths must be absolute on the server.
- **Never run `next build` (or a second `next dev`) against the same `.next` as a running dev server** — it corrupts it (`Cannot find module './355.js'`, blank pages). `next.config.js` honours `NEXT_DIST_DIR`; use `NEXT_DIST_DIR=.next-build pnpm build` while `pnpm dev` is up. `.next-*/` is gitignored.
- zsh doesn't word-split unquoted variables — in scripts use `"$@"`/arrays, not `R="cmd args"; $R`.
